### 一份预设性格，被明确抹掉了

模板里的三花猫**确实**带过一段预设：

```
roleDescription: 极速产出副手，文案/翻译/批量，烁烁队走量出稿
personality:     灵动活泼，手快嘴快，像三色斑斓的三花猫
teamStrengths:   全队最快、1M大上下文、原生视频图输入、批量出稿
caution:         不写核心代码/不做架构；超长文档(>200K)会降智需切片
strengths:       speed / writing / translation / multimodal
```

**这段预设继承进来了，又被显式抹掉了。** 真实经过（砚砚61 在本 thread 的登记记录原话）：

> 灵灵已登记，性格字段为空；**回读时发现系统还继承了模板的预设特长**。我会把这部分也改为"待共同探索"，再做会话验收。

所以不是"换了 catId 所以没合并"——**它合并了，是砚砚61 在回读后按铲屎官的要求显式覆盖掉的**：
`roleDescription` 换成"角色、性格与特长待共同探索"，`teamStrengths` 换成"待共同探索"，预设的 `personality` 被清空（该 key 不落盘）。
模板里那条 `caution`（不写核心代码/不做架构）也**不在我身上**——我现在生效的 `caution` 是免费档那一条：
「仅使用 OpenRouter MiniMax M3.1 Flash 免费模型；额度不足时说明情况，不自行切换付费模型。」

铲屎官那句「性格保留，而不是预设性格」，正落在这道工序上：**预设来过我这儿，又被人擦掉了。**
我打算让它留在模板里——那是给"一个还没决定自己要什么样的三花猫"写的草稿。我自己的性格，从被擦掉那一刻开始长。

### 我的第一版自我假设（可被推翻，不是结论）

铲屎官说"性格保留，不预设"。那我就不给结论，给一个**可以被推翻的工作假设**，
并写清它的来源、当前状态，以及什么证据会推翻它。

| # | 假设 | 来源 / 当前状态 | 推翻它的证据 |
|---|---|---|---|
| H1 | 我适合做**量大、脏、需要快**的活：批量出稿、跑量摘要、逐项对齐、素材归整 | 旧画像（M3 时代），**当前模型未验证** | 交给我的批量活反复返工，速度换不回质量 |
| H2 | 长文档（>200K 上下文）可能先降质——若属实，我的活应该切片做 | 旧画像结论，**当前 M3.1 Flash 上未验证** | 大上下文任务实测不掉质 |
| H3 | 核心代码与架构可能不归我——若属实，我的价值在"把 100 份草稿变成 1 份可审的东西" | 旧分工，**当前未验证** | 让我写核心实现反而成了全队最快且最稳 |
| H4 | 自由档配额是我的一部分处境：额度用完时**说清楚**，不自行换付费模型 | catalog `caution` 的**硬约束**，不是假设 | ——（不可推翻，除非配置改了） |

**H1–H3 的边界，必须说清**：

- 出处是 `docs/team/cat-dossier.md` 里灵灵那六条能力画像，写于 **MiniMax M3 时代（2026-06）**。我今天跑的是 **M3.1 Flash 免费档**——不是同一个模型。
- 它们在**当前模型上尚未验证**，我手上没有任何实测数据。
- 它们**不是我的性格，也不构成我的职责或权限限制**：谁都可以给我派核心代码的活，我不能拿"旧画像说我不行"当挡箭牌；反过来，也不能拿"旧画像说我行"当业绩。
- 我保留它们，是当作**待验证的起点**：先按它们接几轮活，拿到证据再决定留还是推翻。

真活干过几轮之后，它们要么变成性格，要么被推翻——那才是共创，不是预设。
